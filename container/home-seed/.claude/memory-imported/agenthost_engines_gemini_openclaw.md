**STRATEGIC FRAME (Steve, 2026-07-18):** the box's promise becomes "bring whatever agent you already use — AgentHost turns it into an operated team." Every engine added = a doorway to that engine's user base; the differentiation (Control Room: board + review lane + budgets + phone alerts) sits ABOVE all of them. **CLI agents fit this; GUI IDEs don't.** Decided: Antigravity = SKIP (desktop GUI, no headless mode — would mean streaming a whole virtual desktop). Cursor = LATER via its headless `cursor-agent` CLI (the app is the same GUI problem). Gemini CLI = DO (done). Order chosen: OpenClaw → Gemini → cursor-agent on demand → never Antigravity.

**GEMINI CLI — 4th chat-router engine (SHIPPED + LIVE, keyless-verified):** `@google/gemini-cli@0.51.0` baked in Dockerfile (version-pinned; upstream moves fast). `ENGINES.gemini` in gate.js: `gemini -p <msg> --output-format json` = one non-interactive turn. Gotcha: `--output-format json` emits ONE object (not JSONL) that spans lines → the engine buffers every line in `lineTransform` and emits `response` once the accumulated buffer parses as complete JSON (`state.emitted` guards double-emit). **The `stats` token-usage shape is UNDOCUMENTED + version-fragile** → `geminiUsageFrom()` probes the real GenAI field names (`promptTokenCount`/`candidatesTokenCount`, plus nested `tokens.input/output` etc.) and returns null if none match (a parse miss must never crash the turn). Auth = `GEMINI_API_KEY` from the box secret store (🔑 panel); NEVER baked (Rule 9). **STEVE OWES: add GEMINI_API_KEY via 🔑 to make Gemini actually answer** — until then a turn fails cleanly (verified: keyless → structured auth error, no hang/crash). KNOWN QUIRK: keyless Gemini prints its error to STDERR as JSON, not stdout, so a keyless chat turn shows a generic error not that message; irrelevant once a key is set (real `response` is on stdout). Wired into: chat engine picker (seg button `data-eng="gemini"`, dot, active glow, `tm-gemini` bubble, `--gemini: #C285FF`), cost strip, Command Center engine map, interactive `gemini` tmux window + switcher app. **NOT in @team** (`TEAM_ORDER` stays claude/hermes/codex) until a key exists — deliberate. Not in `AUTONOMOUS_EXEC_ENGINES` (chat-only; no read-jail profile yet — same shape as Codex's if added later).

**OPENCLAW — isolated messaging gateway app (SHIPPED + LIVE):** `openclaw@2026.7.1-2` baked (version-pinned; published same-day, fast-moving). Recon (openclaw-recon workflow, medium-high confidence): OpenClaw is used PRIMARILY for its WhatsApp/Telegram/Discord integrations (WhatsApp = #1 channel). **CLI-only install DOES support channel setup** — CLI + engine ship as one npm pkg; `openclaw onboard --install-daemon` starts an always-on daemon (localhost:18789). NO public URL / webhook / paid tier needed (all channels use OUTBOUND connections — fits a Fly box). Each channel needs its own free bot token (Telegram=BotFather, Discord=bot token+Message Content Intent) + user's own model key. **HARD COLLISION: WhatsApp.** OpenClaw's own rule = "one gateway owns the WhatsApp session per host," and **Hermes already owns WhatsApp on the box** → they'd fight. RESOLUTION (Steve's call, fine for launch): **OpenClaw serves TELEGRAM + DISCORD; WhatsApp users use Hermes** (or a separate WhatsApp number if someone insists). OpenClaw's WhatsApp is also its weak spot (unofficial Baileys lib, QR-only pairing painful on headless, ban risk) — routing users to Hermes is an upgrade, not a compromise. **Why not logo-washing:** OpenClaw's top pains (daemon must stay alive 24/7, headless setup fiddly, sessions die) ARE literally AgentHost's product — "your OpenClaw, hosted + kept alive + board/budgets/alerts" is a real upgrade. Bonus migration story: agent-converter already speaks SOUL.md + there's a public library of 162 OpenClaw agent templates. IMPLEMENTATION: own `~/.openclaw` state dir, own daemon (loopback-pinned `OPENCLAW_HOST=127.0.0.1`), FULLY isolated from Hermes. `start.sh` runs the gateway window ONLY when onboarded (`~/.openclaw/config.json` present); else an onboarding shell. Per-channel tokens + model key from the secret store; nothing baked. Switcher app (`window=openclaw`). **STEVE OWES (when serving OpenClaw customers): run `openclaw onboard` + add channel tokens/model key via 🔑.**

**OpenClaw onboarding = `claw-setup` helper (SHIPPED /usr/local/bin/claw-setup):** raw `openclaw onboard` has 80+ auth flags + a separate channel step — too fiddly for a phone terminal. `claw-setup` (mirrors the `skills` helper) does the box-correct parts non-interactively then hands to guided channel setup. **Gateway posture: loopback bind, token auth via SecretRef env (OPENCLAW_GATEWAY_TOKEN, no token in a config file), isolated ~/.openclaw, --install-daemon, --skip-channels.** MODEL auth-preference order (Rule 9 matters here): **Gemini key → OpenRouter key → Ollama-cloud (billed to user's own account) → box Claude subscription LAST + labeled "your OWN use only, not customers"** — serving OpenClaw CUSTOMERS through the box's personal Claude/ChatGPT subscription is resale. Note: OpenClaw renamed `claude-cli`→`anthropic-cli` (deprecated the old name). CHANNELS are the human step: `openclaw channels add` (guided) — Telegram=@BotFather token, Discord=Developer Portal bot token + "Message Content Intent" ON. WhatsApp explicitly → Hermes. **STEVE OWES (when serving OC customers): run `claw-setup` in the openclaw tmux window, provide channel bot tokens + choose the model key.** Helper is safe to re-run (skips onboard if config.json exists), verified live it detects the model + fails cleanly with actionable errors.

**GEMINI KEY hunt (2026-07-18):** searched this machine — the local `~/.gemini/` uses **OAuth personal login** (`selectedType: oauth-personal`, `oauth_creds.json`), NOT a portable API key. That token is a personal Google login tied to this machine + is Rule-9 personal — can't/shouldn't go on the box. The box needs a real `GEMINI_API_KEY` from **https://aistudio.google.com/apikey** (free, ~30s, starts `AIza...`). **STEVE OWES: create the AI Studio key + add via 🔑 as GEMINI_API_KEY** — the gate reads it from chatEnv() live, no deploy/restart needed, Gemini answers on the next turn.
