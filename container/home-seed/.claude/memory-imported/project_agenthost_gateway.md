## The design contract (build to THIS, not a reinterpretation)
Mockup: scratchpad/design-design0.html (session a7596ecb). Components + their backend meaning:
- **In-thread agent attribution**: every AI bubble has `.ah-attr` = a colored dot (Claude=#FF6A3D orange, Hermes=#2ECC71 green, Codex=#6EA8FE blue) + engine name + per-turn cost ("· 4.1K tok · $0.02"). REQUIRES the gate to tag each turn with which engine ran + its token/cost.
- **Engine selector** = segmented pill above the composer (`.ah-seg` Claude/Hermes/Codex, active one tinted). Picks which engine answers. Plus **@codex-style routing** in a message ("· type @codex to route one turn") — the `.ah-routehint` under the composer.
- **Cost strip** (`.ah-cost`): collapsed = one "Spend · today $4.12" figure + a mini stacked bar; expanded = per-engine rows (Claude "sub · Max", Hermes "GLM-5.2 · Ollama" $0.31/890K tok, Codex "ChatGPT · Plus"). REQUIRES per-engine running token/cost accounting persisted on the box.
- **Handoff card** (`.ah-handoff`): when one agent routes work to another, an in-thread card shows "Hermes → Codex", the task, and chips (↳ /brain write, GLM-5.2, est 41K tok). This is the Hermes **kanban** board surfacing as chat events.
- **Task board peek** (`.ah-board`): a bottom-sheet grip showing queued/running/done columns with per-agent cards. This IS the Hermes kanban board (~/.hermes/kanban.db), read via `hermes kanban` CLI / REST.
- **Brain**: `/brain/...` file citations in bubbles; a "brain" tab; the shared Obsidian vault (bridged) + on-box memories, unified across all 3 engines.

## ROUTING MODEL: explicit now, auto-route later (Steve, 2026-07-17)
v1 = YOU route: pick the engine per turn (selector pill) or @mention (@codex) for one turn. Agents SUGGEST handoffs in their replies but Steve approves each ("Do it. Hermes takes X, Codex takes Y" = approval). NO autonomous agent-to-agent dispatch in v1 — that avoids the runaway-cost surface (24.5K tokens/turn!) + the kanban-dispatcher/worker-profile build. Auto-route via the board = opt-in v2 toggle once the token tracker proves costs. This keeps v1 contained: no dispatcher, no worker profiles.

## VERIFIED Hermes invocation (live on box, 2026-07-17) — the router's Hermes engine
- **Use `hermes chat -q "<msg>" -Q -r <session_id> --source tool`** (binary at /data/home/agent/.local/bin/hermes, env HOME=/data/home/agent HERMES_HOME=/data/home/agent/.hermes, run as the `agent` user = the gate's identity).
  - `-Q` = quiet (answer only). `-r <id>` = resume (multi-turn continuity). `--source tool` = hide gateway turns from Steve's own session list. First turn: omit `-r`; capture the new session id.
  - **session id capture**: `-Q` prints `session_id: <YYYYMMDD_HHMMSS_hex>` to STDERR (last line). Parse the FULL id (format has underscores — don't split on `_`). Persist per chat thread so the next turn resumes it.
  - **GOTCHA**: stdout leaks `Warning: Unknown toolsets: hermes-claw-messenger` as a prepended line. Strip known-warning lines from output, or fix the missing toolset. Minor.
  - **NO --usage-file on `chat`** (only on `-z`, which is NON-resumable). So token tracking for Hermes can't use chat's usage-file. Options for Step 3: read Hermes session DB, or a side usage path. NOT a router blocker.
- **`hermes -z "<msg>" --usage-file <path>`**: clean stdout (no warning leak) + PERFECT usage JSON {input_tokens, output_tokens, total_tokens, model:glm-5.2, provider:ollama-cloud, session_id, cost_status} — but each -z is a FRESH conversation (no resume). Use for one-shots where continuity isn't needed; the usage JSON is the ideal tracker format.
- A live GLM-5.2 turn on the box: ~24.5K input tokens (!) for a trivial prompt — the full config/tools/memory context loads every turn. Cost-aware: real turns aren't cheap. cost_status came back "unknown" (ollama-cloud doesn't report $ per call; track tokens, estimate cost separately).
