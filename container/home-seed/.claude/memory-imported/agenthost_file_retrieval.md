**One-time SSH push gotcha (Rule 10/12):** `flyctl ssh sftp put` from Git Bash mangles the remote `/data/...` path to `C:/Program Files/Git/data/...` (MSYS). Fix: prefix `MSYS_NO_PATHCONV=1`. The `sftp shell` heredoc form silently transfers nothing; use `flyctl ssh sftp put -a <app> <local> <remote>` per file.

**The 📁 Files panel** (header button next to 🔑 and 🔔, in `chat.html`): opens a modal listing downloadable files from a CURATED ALLOWLIST of safe folders; tap a file = browser download. Read-only, download-only, no path input, no filesystem browse. Backed by gate.js routes `GET /files` (list) and `GET /files/dl?p=<rootKey>/<name>` (attachment stream). Security model = allowlist not blocklist: `resolveFileRel` realpath-resolves the requested path against the root's realpath and rejects any escape (`../`, absolute, symlink-out, unknown root); dotfiles never listed; 64MB cap; both cookie-gated; downloads audited (`file_download`). A secret/`.env`/key is STRUCTURALLY unreachable because it lives outside every root. Proven by `test/gate-files.test.js` (6 tests, boot-real-gate + attack /files/dl; the secrets file is provably unreachable).

**The allowlisted roots** (gate.js `FILE_ROOTS`): `outbox` (`~/outbox`), `graphics` (`~/agenthost-internal/marketing/graphics`), `renders` (`~/agenthost-internal/marketing/build`), `uploads` (chat image uploads). To add a root, edit FILE_ROOTS.

**`~/outbox` = the agent drop-zone.** `start.sh` mkdirs it every boot. The charter ("Handing a FILE to Steve — the outbox") tells agents: `cp` a finished file there, tell Steve the name, he taps Files → Download. NEVER put a secret in the outbox (it's a human-download surface; Rule 6 read-never still applies).
